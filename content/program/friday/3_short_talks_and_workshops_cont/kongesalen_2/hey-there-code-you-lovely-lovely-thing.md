The world was a very different place before tokens came into the picture. This is a story from that time.

I’m not (only) going to tell you about how, way back in 2018, we got our PO coding, long before AI-assisted coding became a thing.

This is about all the good things we loved about code - about how it made people from different perspectives, backgrounds and roles find common ground. Introducing someone unlikely to the world of programming, letting them go from learning, to understanding, to marveling.

This started with small frustrations piling up into big disasters... well, what good story doesn't?

A tiny localization change. A configuration tweak. A small business-rule adjustment. They spiraled into Trello cards, then planning, then backlog, then development (if lucky) or disappeared into the Bottomless Abyss where some cards are lost forever.

But then we asked ourselves: What if people outside Engineering could read the code and make some of these changes themselves?

What started as a way to reduce back-and-forth on minor changes turned into an 8-year experiment. And somewhere along the way, we realised something bigger: roles have boundaries, but good teamwork doesn’t always need to.

Less friction.
More shared ownership.
More empathy across roles.
More energy for the things that actually matter.

In this talk, I'll share the full story: how we stumbled upon it. The key ingredients for success. What changed for the better. And the pitfalls we did not see coming that caused us to lose it all.

And just because I can, I’m not going to talk about AI at all in this one. I’m sure you’ll find a talk on that elsewhere.

Call this a nostalgia tour if you like. A reminder of what it felt like when the exciting thing wasn't getting code generated for us, but watching someone discover code for the first time.

Come for the story. Stay for the lessons. Maybe leave with a pull request.
